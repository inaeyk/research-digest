# Research Digest v0.5.0

Research Digest v0.5.0 adds the first complete Library workflow while keeping
the application local-first, single-user, arXiv-first, and abstract-level.

## Library

- Browse saved papers in a dense list with search, sorting, and filters.
- Record an optional 1–5 personal interest rating and reading state.
- Maintain human notes, user tags, and collections alongside source metadata.
- Inspect paper detail in this order: Abstract, My Notes, AI Summary, AI
  Discussions.

The dense-list SQL aggregation remains bounded in query count. Rendering cost
still grows with the number of visible rows; pagination and virtualization are
not part of this release.

## Summary lifecycle

Library displays an existing digest summary without invoking a model. Generate
Library summary is an explicit, lazy AI action that creates the first preferred
Library summary. Regenerate summary is shown only when a Library summary is
already preferred. Newly generated prose is governed by artifact retention and
is not copied into every view.

Grandfathered inline digest summaries remain readable. This release does not
mass-copy them into the artifact store or rewrite immutable History.

## AI discussions

Each saved paper can have persistent research discussions. Complete transcripts
are stored locally in SQLite. Only bounded context is sent to the configured
provider; older conversational state may be compressed only when Send or Retry
requires it. Compression does not remove the original local messages.

An assistant takeaway can be reviewed, edited, and explicitly promoted into My
Notes. Promotion itself performs no AI work.

Discussions are grounded in stored title, authors, abstract, notes, summary, and
bounded conversation state. They do not read PDFs, browse the web, or perform
web research.

## AI cost boundary

Startup, Today/Library/History browsing, save/unsave, ratings, reading state,
notes, user tags and collections, deterministic local intelligence refresh,
displaying existing summaries, discussion listing/opening/renaming, transcript
inspection, and takeaway promotion are zero-AI interactions.

AI-capable work consists of manual/CLI/scheduled digest processing; configured
automatic Library-context reasoning during a digest; the explicit Today Find
Library connections action; explicit Library summary generation/regeneration;
discussion Send/Retry; and rolling compression only when one of those
discussion actions exceeds the context bound. Scheduled digest work is opt-in,
and ordinary browsing never silently invokes AI.

## Upgrade and compatibility

- Package version: 0.5.0
- SQLite schema: 20
- JSON config: 5
- Python: 3.11 or newer
- Streamlit: 1.51.0 or newer
- OpenAI Python package for API-provider mode: 1.99.1 or newer

Opening a schema-18 or schema-19 database creates an integrity-checkable
pre-migration backup before migrating additively to schema 20. Articles,
saved/unsaved Library state, notes, tags, collections, feedback, coverage,
corpora, analyses, and History are preserved. New ratings and reading states
remain unset until the user chooses them. Migration performs no model work and
does not copy historical summaries into new artifacts.

The Streamlit 1.51 compatibility repair removes unsupported Today segmented
control keywords while retaining safe defaults and coercion.

The prior declared OpenAI Python 1.99.0 floor cannot load the Responses API
surface used by the production adapters because that wheel contains an internal
missing-event import. Exact 1.99.1 construction and request-shape qualification
passes without credentials or network calls, so 1.99.1 is the smallest corrected
floor.

## Pre-release qualification

The final deterministic qualification completed on August 30, 2026:

- the complete suite passed with 711 tests, 5 intentional skips, and 45
  subtests;
- Ruff, strict mypy, compileall, and diff-whitespace checks passed;
- the complete Today/Library AppTest and callable-signature matrix passed at
  exact Streamlit 1.51.0 and at the current qualified Streamlit version;
- exact OpenAI 1.99.1 construction and Responses API-shape checks passed for
  the Library-summary, discussion, analyzer, and preselector adapters without
  credentials, model requests, or network access;
- a disposable byte-for-byte copy of the schema-18 Linux user database migrated
  to schema 20 with one valid pre-migration backup, preserved aggregate counts,
  no foreign-key violations, and no historical prose copied into AI artifacts;
- the integrated fake-provider workflow preserved rating, reading state, notes,
  explicit summary, discussion transcript, promoted takeaway, History,
  unsave/resave state, and restart state with exact provider-call counts; and
- the fresh independent read-only release audit passed with no blocking, major,
  or minor findings.

The integrated human browser smoke also passed on August 30, 2026, using only a
disposable synthetic database and deterministic fake summary/discussion
providers. It verified Today rendering and save, Library fallback wording,
explicit summary generation and the subsequent Regenerate label, the frozen
Abstract/My Notes/AI Summary/AI Discussions hierarchy, discussion Send,
human-confirmed takeaway promotion, History, unsave/resave, reload/restart, and
the absence of provider activity during ordinary browsing and editing. Only the
explicit fake summary generation and discussion Send invoked their providers.
The authoritative user database and live model providers were not used.

## Deliberately deferred

This release does not add Library virtualization or pagination, transcript
pagination/archive/retention, a History query redesign, per-message model
provenance, historical-summary normalization, dedicated Library model routing
or selection UI, note revision history, takeaway deduplication, Atlas,
embeddings, citation graphs, PDF-grounded discussions, or semantic search.

# Research Digest v0.4.0 release notes

Research Digest v0.4.0 makes source coverage durable and source-scoped, moves
digest execution behind an independently managed worker lifecycle, adds true
application cancellation and UI reattachment, shows article authors, and adds
qualified one-click launch and scheduling support for Windows and macOS.

## Everyday installation and launch

Research Digest requires Python 3.11 or newer.

### Windows 11 with WSL2

Install Research Digest in its WSL environment, then create the owned Windows
Desktop shortcut once:

```bash
research-digest install-launcher
```

Everyday use is a double-click on **Research Digest** on the Windows Desktop.
The shortcut starts or reuses the exact Research Digest UI server and opens the
Windows default browser. Automation uses Windows Task Scheduler.

### macOS

For a source checkout, the guarded bootstrap validates Python before creating
the virtual environment:

```bash
./scripts/bootstrap_macos.sh
source .venv/bin/activate
research-digest install-launcher
```

This installs the owned user-local app at
`~/Applications/Research Digest.app`. Open it from Finder or the Dock; no
Terminal window needs to remain open. Automation uses macOS launchd through an
owned per-user LaunchAgent.

If the Research Digest, Codex, or supporting interpreter installation moves,
rerun `research-digest install-launcher` so the noninteractive launcher records
the current exact executable environment. The app stores no API keys, Codex
tokens, database contents, or other credentials.

## Durable source coverage and reusable work

Coverage now answers whether the complete eligible source article set was
retrieved for a source/category/date scope. Interest Profile edits, relevance
thresholds, model effort, feedback, provider settings, Library state, and
analysis outcomes do not invalidate that source fact.

Completely retrieved source-date corpora remain available locally. Completed
article analyses remain reusable for the same analysis semantics, while missing
or interrupted analysis can resume without refetching an already covered date.
Complete empty dates are covered; incomplete or truncated retrieval is not.

## Worker, UI, cancellation, and scheduler lifetimes

- Closing the browser does not cancel a digest.
- `ui-stop` does not cancel a digest; `research-digest ui-stop` stops only the
  exact owned Streamlit UI server.
- Cancel digest does not disable an installed automatic schedule.
- Stopping or restarting the UI does not start a digest, alter coverage, or
  create a duplicate worker.
- Relaunching Research Digest discovers the active durable run, restores its
  progress display, and keeps **Cancel digest** available.

Explicit cancellation persists a request, terminates only exact run-owned
provider processes, preserves completed work and complete source coverage,
terminalizes the run as `CANCELLED`, and releases durable ownership promptly.

## Article identity

Normal article presentations now show source-provided author names directly
beneath the title. Source order is preserved; long lists compact after five
authors with access to the full stored list. Missing metadata is shown as
`Authors unavailable` without model inference or network work.

## Compatibility and platform qualification

- Package/runtime: 0.4.0
- SQLite schema: 18
- JSON config: 5
- UI registration: 1

No schema or config migration is required solely for this version bump.
Existing historical records, source coverage, Library data, feedback, and
profiles remain in place.

Windows 11 with WSL2 and macOS are human-qualified on their tested
environments. Real-Mac acceptance covered Finder launch, singleton reuse, real
Codex-backed Stage 1 and full analysis, native cancellation, UI reattachment,
fallback ports, and launchd install/status/invocation. Two environment-only
smokes remain deferred: Windows launch plus real Codex execution immediately
after `wsl --shutdown`, and macOS login/logout or full restart.

## Advanced UI lifecycle commands

```bash
research-digest launch
research-digest ui-status --json
research-digest ui-stop
research-digest uninstall-launcher
```

Digest cancellation remains a separate application action through the UI or
`research-digest cancel`; schedule enable/disable remains a separate automation
action.
